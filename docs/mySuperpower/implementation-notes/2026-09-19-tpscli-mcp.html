Task 1 — Project scaffold and the SQL builder · 4ce4597

Task 1 · Done · 4ce4597

Tests are JavaScript importing the built dist/

Decision (spec §8, plan Task 1). Node 20 runs neither .ts files nor --test directory globs, so every test is plain ESM .js under mcp/test/, named one by one in the test script, and tsconfig compiles src/ only. Each later task appends its own file to the script.

  • Builder scope: sql.ts is pure and owns only what the exe accepts as text (bracketed paths, identifier paths, quoting, plain-decimal numbers, 1/0 booleans, no null, offset needs limit); whether a column exists or a value fits stays the exe's (UNKNOWN_COLUMN, VALUE_OUT_OF_RANGE).
  • Plan miscount: the plan expects "11 pass"; the specified test file has 10 test() blocks and 10 pass. No gap.
  • Process: this notes file is controller-owned; the plan's "create/append the notes" steps were redirected into the implementers' report files.

Task 2 — Runner: spawn, timeout, ceiling, response validation · 390a988

Task 2 · Done · 390a988

The fake exe is a real process, and the hang test proves the kill

Decision (spec §5, §9). test/fake-tpscli.js is launched as node fake-tpscli.js <mode>, so the runner is exercised with a genuine child process, pipes and exit codes; no shell and no .cmd wrapper (Node refuses to spawn a .cmd without a shell). The hang mode prints its pid first, so the test can ask tasklist afterwards and prove the tree kill really happened.

  • Two spawn-failure paths, both tested: Node throws synchronously for an argument it cannot pass at all (a NUL byte) and emits error asynchronously for ENOENT; the timer is created before spawn() so the synchronous path settles cleanly.
  • Settle once: every path (close, spawn error, kill failure, kill deadline) goes through one finish() behind a settled flag; a timeout racing a normal close, or taskkill exiting non-zero after the child already closed, cannot double-resolve.
  • Reviewer's minor, deferred: the kill_failed path has no test (plan-mandated test file); verified by reading only.
  • Real exe probe: run(<cli\tpscli.exe>, ['--version']) → exit 0, { ok:true, op:null, version:"0.1.0", complete:true }, no failure.

Task 3 — Server: the eight tools, policy and result shaping · fa89189

Task 3 · Done · fa89189

Gate before resolution; one catch site; the SDK answers schema failures itself

Decisions (spec §3, §6). The write gate runs before file resolution, so a read-only server never reveals whether a file exists. tps_list_files returns bare { files } (nothing ran, so no ok/complete). Every handler refusal (bad column, null value, empty set, blank where, unresolvable file, NUL in the owner) is thrown as InvalidArgument or ToolError and converted to the exe-shaped envelope at one place, attempt(); anything else propagates as a bug.

  • SDK behaviour, verified by running 1.30.0: a zod failure (missing where, limit: -1) is answered by registerTool as an isError text result beginning MCP error -32602: Input validation error, with no structuredContent; the handler never runs. The spec was corrected to say so during planning.
  • Ruling on the reviewer's plan-mandated finding: the per-call stderr line is tool duration exit plus the runner failure kind when there is one; the spec's "tool name, duration, exit code" sentence exists to keep argv (the owner) out of logs, which this line does. Code stands; the spec sentence gains "and the failure kind, if any".
  • Reviewer's minors, deferred: the roots-present + drive-relative name (C:X.TPS) branch is covered only by reasoning (the post-resolve membership check); bracket/column/literal are reached through the builders, not imported directly.

Task 4 — Command line, startup, and the end-to-end run · bff487f

Task 4 · Done · bff487f

Everything that can be wrong at startup fails at startup

Decisions (spec §3). parseArgs rejects an unknown flag, a flag without a value, a non-positive or over-limit --timeout (Node's timer ceiling is 2147483 s) and a --root that is not a folder; discoverExe requires a regular file and treats an explicit --exe/TPSCLI_EXE as the only candidate, so a wrong explicit path fails rather than silently running some other exe. All of it runs in main() before the transport connects; exit 2 with the reason on stderr.

  • Entry guard: main() runs only when process.argv[1] is this module's own path (compared lower-cased), so the tests import dist/server.js without starting a server.
  • e2e cost: both end-to-end tests (real server process, real exe, six copied fixtures) take about 2.7 s, so they stay inside npm test; the suite skips itself with the missing path when the exe or a fixture is absent (proved by renaming the exe once).
  • PowerShell note: < is reserved, so the hand start with stdin closed used cmd /c "node dist\server.js --root ..\cli\testdata < NUL"; it printed tpscli-mcp 0.1.0 ready: exe C:\Projects\GitHub\tpscli\cli\tpscli.exe; roots ...\cli\testdata; writes disabled; owner none; timeout 60s.
  • Reviewer's minor, deferred: the e2e relies on the SDK's StdioClientTransport.close() to end the spawned server; a hard crash mid-test could leave a node process behind.

Final review and fix wave · a7dbca5

Final · Done · a7dbca5

The statement travels on stdin: Windows argv is a quoting layer after all

Deviation from the spec as written (spec §5 corrected). The spec said "the SQL is one argv element; there is no shell and therefore no quoting layer". The whole-branch reviewer pointed out that Windows serialises argv into one command line which Clarion's COMMAND() re-splits. A probe against a copied KEYS.TPS confirmed it: over argv, INSERT ... VALUES (9, '12" pizza', 'Q') is a SYNTAX error and a 40 KB statement fails with spawn ENAMETOOLONG; over stdin, a\"b round-trips byte for byte and the 40 KB statement reaches the parser (where the Clarion runtime's own expression limit rejects it, a CLI ceiling). The exe already read the statement from stdin when given no positional argument, so the runner now pipes the statement on stdin and keeps the flags on argv. The runner ignores EPIPE on that write (an exe that exits before reading), the fake exe gained an echo mode, and the e2e round-trips 12" pizza\ through the real exe.

  • Also fixed: tps_version's stderr line now carries the failure kind like every other tool; mcp/README.md describes the stdin path, the log line and the NUL-owner refusal.
  • Parked with rulings (real, nothing builds on them): taskkill exit 128 after a natural exit in the timeout race is reported as kill_failed; a root folder deleted after startup makes tps_list_files throw past the envelope; a relative --exe is echoed unresolved and duplicate roots list twice; the tests' mkdtemp folders are not removed; no .gitattributes eol rule for mcp/. Deferred from task reviews: kill_failed untested; roots-present + drive-relative name untested; e2e relies on the SDK's close() to end the server child.
  • Ablation pass: no removals; every helper has three or more callers, the single-use names (STATEMENT_OPS, FULLY_QUALIFIED, SelectArgs) carry their comment, and the injected Run is what the twelve server tests stub.
  • Manual gate, still open for the owner: fixtures are copied to %TEMP%\tpscli-manual; register with claude mcp add tpscli -- node "C:\Projects\GitHub\tpscli\mcp\dist\server.js" --root "$env:TEMP\tpscli-manual" --allow-writes, exercise the eight tools once (use the absolute path inside [...] for tps_query; it gets no root resolution), and record the results here.
