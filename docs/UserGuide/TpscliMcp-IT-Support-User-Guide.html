tpscli-mcp

tpscli MCP server — IT Support User Guide

A small Node program that lets an AI assistant (Claude Code, Claude Desktop or any other MCP client) look inside TopSpeed .TPS files and, when you allow it, change rows, by running tpscli.exe on your behalf.

Applies to: tpscli-mcp 0.2.0 · Windows, Node 20 or later, tpscli.exe 0.1.0 · build 1a8c478

tpscli 0.2.0›User Guides›MCP server · IT Support

At a glance

Purpose

Give an assistant nine well-defined tools (describe, select, insert, update, delete, raw query, list files, set roots, version) over .TPS files on the machine that holds them, with writes off unless you switch them on.

Audience

IT and support staff who install the server on a workstation or server, decide which folders and permissions it gets, and read its results when something looks wrong.

Prerequisites

Node 20+, a built cli\tpscli.exe, the repository (or a copy of mcp\dist\, package.json and node_modules\ with the exe beside server.js), an MCP client, and the owner string for encrypted files.

Overview

MCP (Model Context Protocol) is how an AI client discovers and calls tools. This server is one such tool provider: the client starts it as a child process, talks to it over stdin/stdout, and each time the model calls one of the six statement tools the server runs tpscli.exe once and passes the exe's JSON reply back unchanged (tps_version wraps the exe's version reply; tps_list_files reads the folders itself). Nothing is cached, no file stays open between calls, and the server holds no data of its own.

Three things decide what the model can do, and all three are set on the server's command line when you register it:

  • Writes. Off unless the server is started with --allow-writes. Without it, tps_insert, tps_update, tps_delete and any raw write are refused with WRITES_DISABLED before the exe runs.
  • Roots. --root <folder> (repeatable) names folders where bare file names such as KEYS.TPS are looked up, and what tps_list_files lists. A root is a convenience, not a fence: every tool also accepts an absolute path anywhere on the machine the server's account can reach. The set can be replaced while the server runs with tps_set_roots (session only; a restart returns to the flags), and tps_list_files lists any folder given as directory.
  • Owner string. --owner or the TPSCLI_OWNER environment variable supplies the encryption string for every call, so it never has to appear in a conversation. It is never printed.
ScopeThe server does exactly what the exe does: row-level DESCRIBE, SELECT, INSERT, UPDATE and DELETE on one file per call. It cannot create, alter, pack or rebuild a file, join two files or aggregate. The CLI guide beside this one covers the dialect and the exe in detail; this guide covers installing and operating the server around it.

Install and register

Build once

If you have a release zip, skip this: unzip it and go to Register; the exe is already inside dist\.

  1. Install Node 20 or later (node --version should print v20 or higher; this guide was written on v20.18.1).
  2. Make sure cli\tpscli.exe exists (build it from cli\ as its README describes, or copy a built exe into cli\). The server looks for the exe first at --exe / TPSCLI_EXE, then beside dist\server.js, then at ..\..\cli\tpscli.exe.
  3. From mcp\ run npm install, then npm run build. The build writes dist\server.js, the file every client entry points at.
  4. Optionally run npm test: 40 tests, including two that drive the real exe against copies of the test corpus.

Register in Claude Code

  1. From any folder, register the server for every project on this account (-s user). Adjust the path and add the flags you want (see Server flags): 
    claude mcp add -s user tpscli -- node "C:\Projects\GitHub\tpscli\mcp\dist\server.js" --root "C:\pos\data"
    Leave -s user off to register it only for the folder you run the command in.
  2. Confirm it is registered and healthy: 
    > claude mcp list
...
tpscli: node C:\Projects\GitHub\tpscli\mcp\dist\server.js --root C:\pos\data - √ Connected
  3. Servers attach when a session starts. Open a new claude session (or type /mcp in a running one) and ask what tpscli tools do you have?; the assistant lists the nine tools below.
  4. To change the flags later, remove and add again: claude mcp remove -s user tpscli, then the add command with the new flags. The registration lives in %USERPROFILE%\.claude.json.

Register in Claude Desktop

  1. Open %APPDATA%\Claude\claude_desktop_config.json (create it if it does not exist) and add the server under mcpServers: 
    {
  "mcpServers": {
    "tpscli": {
      "command": "node",
      "args": ["C:\\Projects\\GitHub\\tpscli\\mcp\\dist\\server.js", "--root", "C:\\pos\\data"],
      "env": { "TPSCLI_OWNER": "the owner string, if the files are encrypted" }
    }
  }
}
    Backslashes are doubled inside JSON. Append "--allow-writes" to args only when the model may change rows; drop the env block when the files are not encrypted.
  2. Quit and restart Claude Desktop. The tools appear in the tools menu of a new conversation.
TipPoint --root at a folder of copies while you are getting used to what the model does with the tools. Copying the six corpus files from cli\testdata\ into a scratch folder gives a safe playground with known contents (KEYS.TPS has 5 rows; SECRET.TPS is encrypted with owner s3cret).

Server flags

Everything is set on the command line the client uses to start the server (plus two optional environment variables). There is no configuration file.

FlagDefaultNotes
--exe <path>TPSCLI_EXE, else tpscli.exe beside server.js, else ..\..\cli\tpscli.exePath to the exe. When --exe or TPSCLI_EXE is given it is the only place looked at. A missing exe stops the server at startup: tpscli-mcp: tpscli.exe not found; tried C:\nope.exe. Pass --exe <path> or set TPSCLI_EXE.
--root <dir>noneRepeatable. Bare file names resolve inside these folders in order; tps_list_files lists them one level deep. Each must exist: tpscli-mcp: --root C:\nope is not a folder exits 2. Absolute paths are accepted whether or not they are inside a root. tps_set_roots replaces the set for the session.
--allow-writesoffEnables tps_insert, tps_update, tps_delete and raw writes through tps_query. Without it they are refused with WRITES_DISABLED; parse_only raw statements are always allowed.
--owner <string>TPSCLI_OWNER, else noneOwner (encryption) string used for every call that does not pass its own owner argument. Never printed, not in the ready line, not in errors. A call may override it with its own owner, but prefer the server-wide setting so the secret stays out of the conversation.
--timeout <seconds>60Wall-clock limit for one exe run. Past it the server kills the whole process tree with taskkill /T /F and answers INCOMPLETE; if that kill itself fails the message says the exe may still be running. Maximum 2147483.

Startup problems (an unknown flag, a missing exe, a missing root) exit 2 with one tpscli-mcp: ... line on standard error, and the client shows the server as failed. A healthy start prints one ready line, for example tpscli-mcp 0.2.0 ready: exe C:\Projects\GitHub\tpscli\cli\tpscli.exe; roots C:\Projects\GitHub\tpscli\mcp\work; writes disabled; owner none; timeout 60s, then one line per exe run: tpscli-mcp tps_insert 412ms exit 0 (with the failure kind appended when there was one). tps_list_files and refusals that stop before the exe do not log. Statements, arguments and the owner string are never logged.

Caution--root does not limit what the model can reach. Any tool accepts an absolute path, and tps_query uses the path in the statement exactly as written. The server runs with the permissions of the account that started the client; give that account read-only access to folders it should never change, and keep --allow-writes off unless the session needs it.

The nine tools

The model chooses the tool and fills in the arguments from what you ask it in plain words; you rarely type these names yourself. Knowing them tells you what the assistant can and cannot do, and what the entries in its tool log mean.

ToolArgumentsWhat it runsNeeds
tps_versionnonetpscli.exe --version; returns { "server": "0.2.0", "exe": { ... "version": "0.1.0" ... }, "roots": [...] }nothing; the quickest health check
tps_list_filespattern? (default *.TPS), directory?no exe; lists directory or, without it, the roots, one level deep: name, path, size, modifieda root or directory
tps_set_rootsroots (string[])no exe; replaces the root set for this session and returns it; [] clearsexisting folders, absolute
tps_describefile, owner?DESCRIBE [file]: record count, encrypted, every column with type and size, every keyread access
tps_selectfile, columns?, where?, order_by?, limit?, offset?, format?, owner?a built SELECT; no limit = exe default 1000 rows, 0 = no cap, offset needs limit; format: "table" returns the text gridread access
tps_insertfile, values, owner?a built INSERT of one row; values maps column to value--allow-writes
tps_updatefile, set, where, owner?a built UPDATE ... WHERE; returns matched and affected--allow-writes
tps_deletefile, where, owner?a built DELETE ... WHERE; returns matched and affected--allow-writes
tps_querysql, owner?, limit_default?, parse_only?, format?the statement verbatim; the [file] in it is used as written, no root lookup (give a full path)--allow-writes for a write; parse_only always allowed

file is an absolute path or a bare name resolved inside the roots. where and order_by are fragments in the exe's dialect without the keyword ("ID < 3", "NAME DESC"). Values: strings, numbers (DECIMAL columns take numbers, never quoted strings), booleans as 1/0, dates 'YYYY-MM-DD', times 'HH:MM:SS.hh', BLOBs as base64. null is refused because TopSpeed has no NULL: omit the column instead. A blank where on an update or delete is refused, so the model cannot touch every row by accident; WHERE 1 = 1 still can, on purpose.

Procedures

Check the server from the command line

mcp\tools\call.js starts the server with the flags you give it, calls one tool with a JSON object read from standard input, prints the result and exits 0 (the tool answered), 1 (the tool answered with an error) or 2 (the call never got an answer: no tool name, arguments that are not JSON, or a server that could not start). It needs no client and is the fastest way to reproduce what the model saw. From PowerShell, in mcp\:

  1. Version, no arguments: node tools\call.js tps_version prints { "server": "0.2.0", "exe": { "ok": true, "op": null, "version": "0.1.0", "complete": true }, "roots": [] }.
  2. Describe a file inside a root, keeping the JSON in single quotes so PowerShell leaves it alone: 
    '{"file":"KEYS.TPS"}' | node tools\call.js tps_describe --root C:\pos\data
  3. Rows as a grid: 
    > '{"file":"KEYS.TPS","columns":["ID","NAME","CODE"],"order_by":"ID","limit":3,"format":"table"}' | node tools\call.js tps_select --root C:\pos\data
ID  NAME     CODE
--  -------  ----
 1  Able     A
 2  baker
 3  Charlie  C
(3 rows, truncated by LIMIT)
  4. Standard error is inherited, so the ready line and the per-run line appear in the same window; that is where to look when the client only says the server failed.

Let the model look at a file

  1. Ask in plain words: describe C:\pos\data\ITEMS.TPS, or with a root configured, describe ITEMS.TPS. The assistant calls tps_describe and summarises the columns, keys and record count.
  2. Ask for rows: show the first ten rows ordered by SKU, find the rows whose DESC starts with "b", show that as a table. Each becomes a tps_select; you can expand the tool call in the client to see the exact arguments and the raw response.
  3. where and order_by take whole fragments ("CODE IN ('A','E') AND AMOUNT > 5", "AMOUNT DESC, ID"), so most requests stay in tps_select. When the assistant wants a statement written out in full, or a dry run with parse_only, it uses tps_query. The [file] in that statement is used exactly as written, with no root lookup, so it should be a full path.

Change the working folder without restarting

  1. Ask: work in C:\pos\data from now on. The assistant calls tps_set_roots with that folder; the result lists the roots now in force. Bare names such as ITEMS.TPS resolve there and tps_list_files lists it.
  2. For a one-off look at another folder ask list the TPS files in D:\backup; that is tps_list_files with directory and leaves the roots alone.
  3. The change lasts for the session. A new session starts from the registration's --root flags again; tps_version shows the current set at any time.

Enable writes for a session, safely

  1. Copy the .TPS file first. Neither the exe nor the server has an undo.
  2. Register (or re-register) the server with --allow-writes. Until then every write is refused before the exe runs: 
    { "ok": false, "complete": true, "op": "delete",
  "error": { "code": "WRITES_DISABLED",
             "message": "This server was started without --allow-writes, so INSERT, UPDATE and DELETE are refused. Restart it with --allow-writes to enable them." },
  "outcome": "none" }
  3. Ask the model to look before it writes: show the rows where SKU = '000379493', then set RECALLED to 0 on them. The tool descriptions tell it the same thing, and tps_update replies with matched and affected so you can compare against the select.
  4. Have it confirm with the same select afterwards, and check the client's tool log for the outcome field on any failure ("none", "rolled_back" or "unknown").
  5. When the work is done, re-register without --allow-writes.
CriticalA result whose error.code is INCOMPLETE means the server did not get a valid, complete reply from the exe (timeout, crash, output over 64 MiB, or a reply without "complete": true) and, for a write, "outcome": "unknown": the change may or may not be in the file. Neither the server nor the model retries it. Select the rows and decide from what is actually there, exactly as the CLI guide says for a reply with no "complete": true.

Work with encrypted files

  1. Put the owner string in the server's environment, not in the chat: Claude Desktop takes an env block (see Install); for Claude Code set TPSCLI_OWNER in the environment the claude command inherits, or add --owner <string> to the registration command.
  2. Without it, an encrypted file answers OWNER_REQUIRED: "Not a plain TopSpeed file; if it is encrypted pass --owner". A wrong string answers OWNER_WRONG: "Owner string does not decrypt this file". tps_describe on a correctly opened encrypted file reports "encrypted": true.
  3. The string is never echoed: not in the ready line (owner none / owner set), not in any error, not in the per-run log line. If a colleague reports OWNER_WRONG, compare the string in the registration against its source of truth.

Move the server to another machine

  1. Copy the whole mcp\dist\ folder (server.js imports runner.js and sql.js beside it) together with mcp\package.json and mcp\node_modules\ (after npm ci --omit=dev in mcp\), keeping the same layout: package.json and node_modules\ in the parent of dist\. Put tpscli.exe inside dist\, beside server.js; that location is first in the exe search order, so no --exe flag is needed, or simply copy the release zip and unzip it there.
  2. Install Node 20+ on the target and register the server as above with the new path. npm publish is not part of the workflow: the package is marked private and is useless without the Windows exe.

Reading a result

For the six statement tools the result is the exe's own response object, delivered twice: as structured data for the model and as pretty-printed JSON text you can read in the client's tool log. isError is set whenever the exe exited non-zero or the server refused the call, so the model knows to explain rather than carry on.

ResultWhat you seeMeaning
Success{ "ok": true, "op": "update", "matched": 1, "affected": 1, "complete": true }The exe ran and exited 0. Members depend on the statement, exactly as in the CLI guide.
Exe error{ "ok": false, "op": "select", "error": { "code": "UNKNOWN_COLUMN", "message": "Unknown column NOPE; valid columns: ID, NAME, CODE, AMOUNT", "position": 67, "token": "NOPE", "column": "NOPE" }, "outcome": "none", "complete": true }The exe rejected or failed the statement; its codes and exit codes 1, 2, 3 are the CLI's.
Server refusal{ "ok": false, "complete": true, "op": "insert", "error": { "code": "INVALID_ARGUMENT", "message": "NAME: null is not a value (TopSpeed has no NULL); omit the column instead" }, "outcome": "none" }The server stopped the call before running the exe. Same shape as an exe error so the model sees one format.
Incomplete"error": { "code": "INCOMPLETE", "message": "... The response is incomplete and the write outcome is unknown; do not retry without checking the file." }, "complete": false, "outcome": "unknown"Timeout, crash, spawn failure, output over 64 MiB, or no valid response object. Also carries exit_code, timed_out and the exe's stderr.
Tablethe aligned grid as plain text, last line (n rows) or CODE: messageformat: "table"; not available for writes because the grid drops the outcome field.
Bad argumentsMCP error -32602: Input validation error: Invalid arguments for tool tps_select: Expected number, received string at limitThe protocol layer rejected the call (wrong type, missing required field) before the server's handler ran. The model normally corrects itself and calls again.

The server's own codes: WRITES_DISABLED, FILE_NOT_FOUND (a bare name not in any current root, or a relative path that escapes the roots), INVALID_ARGUMENT (empty set or values, blank where, bad column name, null, exponent or unsafe number, offset without limit, ] in a path, table format on a write, a NUL byte in the owner string, a relative or missing folder for tps_set_roots or directory, tps_list_files with neither roots nor directory) and INCOMPLETE. Everything else comes from the exe.

Troubleshooting

SymptomLikely causeFix
The assistant says it has no tpscli toolsThe session started before the server was registered, or it was registered for another folder.Run claude mcp list. If tpscli is there, start a new session or type /mcp; if not, run the add command again, with -s user for every project.
claude mcp list shows the server failed; stderr says tpscli-mcp: tpscli.exe not found; tried C:\nope.exe. Pass --exe <path> or set TPSCLI_EXE.The exe is not where the server looks.Build or copy cli\tpscli.exe, put the exe beside dist\server.js, or pass --exe. Reproduce with node tools\call.js tps_version, which prints the line.
tpscli-mcp: --root C:\nope is not a folder, exit 2A root in the registration does not exist (or the client quoted it oddly).Fix the path; every root must exist when the server starts. Quote paths with spaces.
tpscli-mcp: unknown option --bogus, exit 2A misspelt flag in the registration.Only the five flags in Server flags are accepted.
"code": "INVALID_ARGUMENT", "message": "The server has no root folders; pass directory, or call tps_set_roots first."tps_list_files without directory on a server with no roots.Ask for the folder by name (directory) or have the assistant set it as a root; re-registering with --root is no longer needed.
"code": "FILE_NOT_FOUND", "message": "NOPE.TPS not found inside C:\pos\data"A bare name that is in none of the roots, or a relative path.Check the spelling against tps_list_files, or give the absolute path, or set the folder with tps_set_roots. The message names every root that was searched.
"code": "WRITES_DISABLED", "outcome": "none"A write on a read-only server. Nothing ran.Intended. Re-register with --allow-writes only for the session that needs it (see the procedure above).
"code": "INVALID_ARGUMENT", "message": "format \"table\" is not available for a write: the grid drops the outcome field"The model asked for a grid on an insert, update or delete.Nothing to fix; the model retries without format. Writes always come back as JSON.
"code": "OWNER_REQUIRED" or "code": "OWNER_WRONG", exit 2Encrypted file with no or the wrong owner string.Set TPSCLI_OWNER / --owner in the registration. The server will not show you the string it used.
"code": "INCOMPLETE", "timed_out": trueThe exe ran past --timeout (default 60 s); the server killed its process tree (the message says so if the kill did not succeed).For a read, narrow the statement or raise --timeout. For a write, treat the outcome as unknown and inspect the rows before doing anything else.
"code": "INCOMPLETE", "exit_code": -1073741819 or another value outside 0 to 3The exe crashed. If it stopped behind a modal dialog, the timeout kill removed it.Look at the machine for a dialog; check the exe against the CLI directly with the same statement (the CLI guide's troubleshooting applies).
MCP error -32602: Input validation error: Invalid arguments for tool ...The model sent a wrong type (a string for limit, a missing where).Normal; the model reads the message and corrects the call. If it keeps happening, the tool descriptions are in mcp\src\server.ts.
The model changed rows in a file you did not expectAbsolute paths are accepted anywhere, and --allow-writes was on.Roots do not fence writes. Turn writes off between sessions and run the client under an account whose file permissions match what the model may touch.
